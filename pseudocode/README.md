# Pseudo‑code

Plain‑English walkthroughs of the load‑bearing tools in Kipple Index — the ones that earn their keep and whose patterns are worth borrowing.

The convention is **`[PCODE]`** in the article index (`../ARTICLE_INDEX.md`): any article marked `[PCODE]` will have a matching file in this directory, named after the tool it walks through.

## Why pseudo‑code and not the actual code

The private working tree carries entanglements — file paths, database identifiers, references to personal incidents — that aren't useful to anyone outside the author's head. The pseudo‑code in here is the *shape* of the tool: variables renamed for clarity, side branches collapsed when they're noise, the bug history annotated inline. The point is for the next person building something similar to be able to read it, understand the trade‑offs, and write a better version for their own system.

Where a pseudo‑code file describes a tool with an existing architecture doc in [`../docs/`](../docs/), the two will cross‑link.
